### 5. [LOW] The same input is read 2 times (ExistingRDD (pre-computed DataFrame, e.g. a foreachBatch micro-batch))

_rule `SD207`; category io; confidence medium; SQL queries 15, 16_

Work is repeated because a source is re-scanned by several actions.

**What the metrics show**

- ExistingRDD (pre-computed DataFrame, e.g. a foreachBatch micro-batch) is scanned by 2 different queries: 15, 16.

**Why it is slow**

The same pre-computed DataFrame (typically the micro-batch inside foreachBatch) is re-computed for every action on it. Spark cannot push column pruning into it, so each action re-reads the full source, including large columns you do not need for that action.

**What to do**

1. _code_: **Persist the micro-batch once, run every action on the persisted copy, then unpersist**. Persist after cheap narrowing (filters/column selection) but before expensive work you reuse.

   ```python
   def process(batch_df, batch_id):
       df = batch_df.filter(...).persist()
       try:
           keys = df.select('dlog_date').distinct().collect()
           # ... MERGE using df ...
       finally:
           df.unpersist()
   ```
2. _code_: **Compute small side values (key lists, counts) from narrow columns only, and avoid extra actions where possible**
